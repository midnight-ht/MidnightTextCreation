# 账号、平台风格与发布状态管理设计

日期：2026-10-04。状态：用户已确认并授权实施；本地管理功能已实现，真实平台验收待完成。

## 目标与已确定范围

在现有 midnight-advertorial Skill 内新增账号内容管理能力：账号下管理平台绑定、风格预设、输出目录与内容版本；从内容记录一键打开目标编辑页并填充；关联发布内容后主动回收最新状态。首批平台由用户指定为微信公众号、今日头条、小红书。

现有基础：scripts/run_skill.py 已支持任务级 output_dir、平台配置和 Markdown 导出；scripts/editorial.py 只接收并追加用户提供的指标，不主动访问平台；平台排版库覆盖不同内容形态。当前没有管理服务、浏览器执行器或发布状态查询器，也没有 Git 仓库或 CodeGraph 索引。

## 方案选择

1. 推荐：本地管理页 + 本地持久化 + 可插拔平台适配器。支持账号、风格、内容列表与按钮操作，复用 Python 本地流程；浏览器执行及回收以独立适配器接入。
2. 仅 CLI/JSON：维护成本较低，能完成配置与回收，但无法直接满足可见的一键操作体验。
3. 云端多用户系统：可跨设备协作，但引入登录、托管与部署需求，超出当前技能内部增强范围。

第一版采用方案 1，不引入云端部署。管理服务仅监听本机；编辑页使用用户已登录的浏览器会话。真实平台接入依赖已登录账号和现场页面验证，通用配置与模拟不能替代平台验收。

## 数据关系

Account → PlatformBinding → StyleProfile → ContentVersion → Publication → StatusSnapshot。

- Account：稳定 account_id、显示名、启用状态。允许同一平台多个账号。
- PlatformBinding：binding_id、account_id、平台键、平台账号标识、编辑页地址、默认风格与输出根目录、适配器配置。每个绑定必须能核对当前浏览器身份。
- StyleProfile：风格名称、目标读者、目标语气、作者样文、禁用主张、语言、格式、style_guidance、审稿门槛及版本。每个绑定可以有多个风格预设。
- ContentVersion：content_id、version_id、绑定和风格版本、输入、实际标题/封面文字/摘要/正文/标签、文件列表、审稿状态及内容摘要。版本发布后不原地覆写。
- Publication：publication_id、对应内容版本、平台内容 ID/链接、发布渠道、实际发布时间与关联证据。手工关联与平台确认分别记录。
- StatusSnapshot：发布关联、source（api/browser/mock）、observed_at、平台原始状态与归一化状态、指标、查询结果、错误及脱敏证据。

本地持久化采用 SQLite，配置提供 JSON 导入导出。运行数据和导出文件不写入示例配置；密码、Cookie 和 Token 不进入账号文件或内容台账。接口凭证仅引用本机环境变量或授权凭据存储。

## 配置合并与输出目录

优先级：任务显式覆盖 → 选定风格配置 → 账号平台绑定默认值 → 技能默认值。facts 保持当前任务证据，禁止从其他内容或作者样文自动借用。

输出根目录支持中文、空格及 Windows 绝对路径。相对目录以配置文件所在目录解析，界面展示最终绝对路径。账号级默认目录可以被平台绑定覆盖，再由单次任务覆盖。

管理模式导出结构：<输出根目录>/<account_id>/<platform>/<content_id>/<version_id>/。每版写正文 Markdown、完整 publication.json 与 manifest.json；原有不带账号的 CLI 行为继续兼容。

对不存在的目录按用户配置创建；不可写、空路径、路径逃逸或碰撞报错，不静默回退到技能目录。导出成功后记录真实文件路径；失败记录错误，不登记为交付完成。写入其他受限目录仍须遵守运行环境的文件权限。

## 本地管理页与操作

页面提供账号列表、平台绑定、风格预设编辑、输出目录设置、内容与版本列表、发布记录及最新状态。

主要按钮：生成/导入内容、查看输出目录、打开并填充、关联已发布内容、立即回收、启用/停止状态轮询。

“打开并填充”创建绑定实际版本的任务，界面显示执行中、需要登录、账号不匹配、部分填充、完成或失败。只有浏览器执行器完成读取校验后才显示填充完成。仅打开链接、复制正文或生成填充计划均不算填充完成。

管理接口包含配置读写、内容生成/导入、导出、填充任务创建/查询、发布关联、状态回收与历史查询。所有本地变更请求要求会话校验，并验证请求来源，避免外部网页驱动本地写操作。

## 页面填充适配器

每个平台分别实现能力清单、登录检测、账号核验、编辑页发现、字段映射、富文本/纯文本填充、素材上传及读取校验。通过已授权浏览器工具执行；不通过保存明文登录凭据获得会话。

只填充该版本实际存在、且平台支持的标题、正文、摘要、标签与媒体。图片/视频上传要求文件真实存在且类型可接受；小红书图文缺少图片时报告缺素材，不能仅填文字就宣称图文完成。

填充前核对域名、页面、登录状态和账号；发现已有非空草稿时不直接覆盖，提供新建或合并选择。填充后读取字段，确认标题、正文及必要素材一致。页面变化、选择器不唯一、验证码和登录失效返回可操作错误；保留已填草稿，不反复追加。

默认停在草稿，不点击发布。实际发布授权继续遵循现有生产规范。恢复任务使用 task_id 与内容版本摘要，避免重复创建或误填其他版本。

真实适配器只有通过对应平台当前页面测试后才标记 verified；未验证的适配器保持 unverified/unsupported，管理页如实展示。模拟平台另行提供完整一键操作验收链路。

## 发布状态回收

归一化业务状态：unknown、draft、scheduled、processing、published、rejected、removed；原始平台状态同时保留，无法映射时使用 unknown。查询任务另记 succeeded、failed、unsupported 等状态，避免将查询失败解释为下架。

- api：使用正式授权的接口或用户提供的接口契约查询，限制到绑定平台/账号/内容；校验返回 ID、业务错误、字段类型和时间。通用 HTTP 适配器可通过本地模拟 HTTP 服务测试，不代表三个平台均具备开放接口权限。
- browser：官方接口不可用时，在已登录创作者后台读取状态与可见指标；必须核对账号与内容 ID/链接，不从相似标题猜测匹配。
- mock：使用确定性的模拟记录演示审核中、发布、驳回、删除及失败；醒目标注模拟，模拟状态与指标不进入真实发布反馈。

每条快照显示来源、观测时间、最后成功时间和新鲜度。回收失败保留上次成功结果，并显示失败，避免用旧缓存冒充实时。指标不可用为 null，不以 0 替代。

“实时”采用可配置轮询：默认 60 秒一次，页面显示最新观测时间；提供立即回收、停止、超时、重试与退避。实际平台限流或指标延迟时按平台能力调整频率，不承诺秒级平台同步。轮询使用本地服务任务生命周期，不擅自创建 Codex 自动化。

只有真实快照具备合法发布时间和观察窗口时，才转换为现有 editorial 反馈记录；状态回收本身不证明传播效果或因果关系。

## 文件与接入范围

新增账号/风格与发布记录 Schema、配置示例、管理与适配器模块、本地管理服务/页面、模拟平台与测试。改动 run_skill.py 接入配置合并和账号隔离导出，保持旧 CLI；更新 SKILL.md、README.md、manifest.json 与生产任务模板。

n8n 仍一次处理一个平台。管理层先解析绑定和风格，再将 style_guidance、素材及审稿配置传给模型流程；模型输出进入同一内容台账。浏览器动作和回收不依赖模型输出自称成功。

## 验收与测试

1. 同一平台两个账号可拥有不同风格和输出目录，生成内容及状态历史互不串号。
2. 配置保存、重启读取、JSON 导入导出有效；非法平台/格式、重复 ID 和缺失绑定报错。
3. 任务覆盖优先级、中文/空格路径、不可写目录、路径逃逸和版本不覆写都有行为测试。
4. 原有无账号 runner 和平台布局检查通过，不改变既有结果状态含义。
5. 模拟编辑页一键完成打开、填充和回读校验；覆盖登录失效、错账号、非空草稿、缺素材、部分失败与幂等恢复。
6. 本地模拟 HTTP 服务覆盖 published/rejected/removed、401、限流、超时、畸形响应和内容 ID 不匹配；明确标注测试来源。
7. 状态新鲜度、错误保留上次结果、停止轮询、退避及缺指标为 null 都有检查。
8. 微信公众号、今日头条、小红书分别在真实登录会话验证填充、账号匹配、草稿完整性与发布后读取。需要用户提供账号会话和实际已发布内容；缺少时报告未验收，不写成通过。
9. 真实页面操作停在草稿；无明确发布授权时不触发发布。

## 待用户确认的设计选择

推荐采用本地管理页、账号隔离的版本目录、一键填充后保留草稿、60 秒可配置轮询，并以真实适配器与模拟适配器分别交付。平台范围已经确认，以上设计已获用户确认并完成本地实现；现场平台验收仍需实际登录会话与页面映射。
