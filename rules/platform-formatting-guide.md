# 国内外平台内容与排版手册

更新：2026-10-04。此文件给出编辑方法，不承诺流量，不代替平台政策。可执行配置以 `platform_layouts.json` 为准；每次发布仍应在目标账号的原生编辑器预览。

## 先选平台，再选内容形态

同一观点不是复制到所有平台。先确定读者问题、事实和来源，再按平台调整信息顺序、标题、开头、长度与视觉表达。不得为了适配删掉影响结论的限制条件，或增加不存在的经历、统计和案例。

| 形态 | 内容顺序 | 排版方式 | 交付内容 |
| --- | --- | --- | --- |
| `long_form` | 导读 → 问题 → 分节论证 → 证据与边界 → 结论与来源 | 原生小标题、自然段、少量加粗、引用与图注；技术文保留代码块 | 标题、摘要、完整正文、小标题和来源 |
| `short_post` | 首屏具体判断 → 背景或依据 → 结论或讨论点 | 短段之间空行；少量并列项，不用花体字符伪造加粗 | 标题候选、首屏、正文、必要链接 |
| `carousel` | 封面主题 → 场景 → 逐卡证据或步骤 → 边界或行动 | 每张一个主题，主题/小标题/正文三级层次，手机预览字号、裁切与安全区 | 卡片顺序及文案、发布说明、封面文字、素材需求 |
| `thread` | 首条主题和承诺 → 各条连续推进 → 结论 | 每条独立成段，编号可选；按原生加权计数检查，不机械切长句 | 按顺序的独立帖子，不静默截断 |
| `script` | 开场看点 → 背景 → 证据、过程或演示 → 结论 | 一段一个口播单元；画面、字幕与口播分开，按真实时间轴定字幕 | 完整口播、待补镜头清单、简介与来源；无素材不编造时间戳 |
| `spoken` | 场景或问题 → 解释 → 动作建议 | 短句自然换行，停顿按语义；不插入制作说明 | 可朗读工作稿，仍需试读 |
| `text` | 保留原有逻辑 | 尽量保留原文，不作平台包装 | 干净正文工作稿 |

卡片数量、每段句数、正文长度是编辑取舍，不是这里强制的平台上限。没有证据时不能写“平台最推荐某长度”“某标签一定带来流量”。

## 国内平台

| 平台键 | 默认形态 | 内容和排版重点 |
| --- | --- | --- |
| `wechat` 公众号 | 长文 | 标题和摘要分开；小标题推进判断；正文左对齐优先，引用、图注和来源贴近相关论点；检查手机阅读 |
| `toutiao` 头条 | 长文 | 问题与判断前置，中短自然段；微头条显式选短帖，不靠冲突标题脱离事实 |
| `xiaohongshu` 小红书 | 卡片 | 封面兑现主题；图内文字和发布说明分开；卡片之间保持顺序、层次与视觉一致；标签只取相关主题 |
| `douyin_long_text` 抖音图文 | 卡片 | 一张一个场景或动作，末张写具体提醒；说明不是完整口播，口播用 spoken |
| `douyin_video` 抖音视频 | 脚本 | 第一段进入问题；展示真实对象或过程；字幕不挡主体与按钮；封面、标题、口播一致 |
| `wechat_channels` 视频号 | 脚本 | 具体场景与可信解释，分享价值来自内容；封面和简介不要与实际讲述错位 |
| `weibo` 微博 | 短帖 | 首段观点与背景，正文自然分段；话题、提及和链接在编辑器确认，长内容另作长文 |
| `zhihu` 知乎 | 长文 | 回答先直接回应问题，专栏标题单独填写；推理、反例、来源和适用边界分层 |
| `bilibili` B站专栏 | 长文 | 小标题与可视化例子；解释图放在对应论点后，来源与图注齐全 |
| `bilibili_video` B站视频 | 脚本 | 开场看点、内容推进、可展示案例、结论；简介附来源，章节依据真实时间轴 |
| `baijiahao` 百家号 | 长文 | 准确标题、事实型分节、克制图片；解释性信息优先于情绪包装 |
| `kuaishou` 快手 | 脚本 | 真实生活场景，少书面腔；图文显式用 carousel，内容不可虚构亲身经历 |
| `juejin` 掘金 | 长文 | 问题 → 环境 → 复现 → 原因 → 方案 → 验证 → 取舍；代码块标语言，保留版本和实际证据 |
| `csdn` CSDN | 长文 | 目录对应已有标题；代码、日志、运行结果分开；来源与版本明确，不编造成功截图 |
| `jianshu` 简书 | 长文 | 叙事或评论自然分节，保持作者判断；按当前编辑器选择 Markdown 或富文本 |

## 国外平台

| 平台键 | 默认形态 | 内容和排版重点 |
| --- | --- | --- |
| `medium` | 长文 | 清晰主论点、现场和推理；标题、副标题分别填，使用 story editor 处理层级、列表、引用与链接 |
| `substack` | 长文 | 作者观察、判断、依据、边界；导读适合邮件首屏，同时预览邮件和网页 |
| `linkedin` | 短帖 | 工作决策、约束和证据前置；段间空行；避免夸大成绩和 Unicode 花体；长文用文章入口 |
| `linkedin_article` | 长文 | 标题、封面、正文分开；案例突出工程或经营取舍，结论可复用 |
| `x_thread` | 线程 | 每条推进一件事；来源靠近论点；普通帖与订阅长帖权限分开核查，加权长度以编辑器为准 |
| `threads` | 线程 | 首条清楚，回复形成连续论证；不要每条重复首句；账号功能和长度发布时核查 |
| `instagram` | 卡片 | 图内文案为主，caption 补背景；网格封面裁切与卡片字号在手机预览 |
| `instagram_reels` | 脚本 | 动作、口播与字幕配合；说明不是逐字字幕；封面裁切与安全区单独检查 |
| `tiktok` | 脚本 | 具体场景和快速解释；照片形态用 carousel，文字形态用 short_post；字幕时间依据实际视频 |
| `youtube_community` | 短帖 | 观察或具体问题开场；投票选项不重叠；说明图片在讨论中的作用 |
| `youtube` | 脚本 | 缩略图与标题兑现内容；正文脚本有完整推理；简介交代内容、来源和真实章节 |
| `youtube_shorts` | 脚本 | 单一清晰主题，动作或演示与解说结合；上传时核对实际画幅、时长及版权资格 |
| `facebook` | 短帖 | 补足背景、可扫描分段；图片文字与说明互补；群组先查群规，避免互动诱饵 |
| `reddit` | 社区长文 | 背景、已尝试方法、证据与明确问题；按 subreddit 规则选择 flair，披露关联关系；区分富文本和 Markdown |
| `pinterest` | 卡片 | Pin 标题、图上文字、说明与落地页一致；突出具体用途，检查目标链接与图片权利 |
| `quora` | 社区长文 | 先回答问题，再解释依据和边界；来源可核查，不把答案写成导流广告 |

通用入口：`blog` 为独立博客长文；`seo_article` 先回答搜索意图；`generic` 保留原文。它们不是独立社交平台。

## 排版示例与边界

以下只用同一段示意材料展示信息分块，不代表真实发布成效，也不是虚构事实证据。

材料：“发布前先核对标题和正文。标题承诺的内容需要在正文找到依据。图片里的文字也要一起检查。”

长文：把三句话保留为自然段；如果作者有真实例子，可另写“检查对象”“检查方法”“适用边界”等节标题，但本地脚本不凭空补节。

卡片：第一张“发布前先核对标题和正文”；第二张“标题承诺的内容需要在正文找到依据”；第三张“图片里的文字也要一起检查”。这些只是卡片文案工作稿，尚未形成图像，也未证明三张是最佳数量。

线程：分别发三条，第二条承接第一条；每条发布前检查计数。不能把整段编号 body 当作一条帖发布。

口播：按这三个语义单位试读；拍摄时另行补真实镜头，不能依据文字生成假时间轴。

## 本地与模型模式

本地输出 `platform_output.layout_plan`：`platform`、`format`、`body`、有序 `blocks`、内容顺序、段落/强调/配图方法、原生编辑器注意事项、发布步骤与警告。仅基于原文分块，`semantic_adaptation=not_evaluated`；不翻译、不语义压缩、不渲染富文本、不生成图片或视频、不发布内容。

模型工作流从同一 JSON 注入 `platform_profile` 和 `format`，按形态重写完整正文；用空行分隔卡片、帖子或口播单元。每次最终修订后重新生成分块计划，四维审稿检查实际发布标题、封面和正文。原生效果必须人工预览，流程模拟通过不等于平台验收。

## 来源与更新方式

以下只支持编辑器能力或发布形态，不支持“最佳长度”或“爆款保证”。国内平台公开帮助信息不完整，本版本国内细则明确属于编辑建议，字符数、标签数、比例、权限等硬限制未作通用自动校验。

- [Medium story editor](https://help.medium.com/hc/en-us/articles/215194537-Using-the-story-editor)：原生标题、强调、引用、链接和列表。
- [Reddit Formatting Guide](https://support.reddithelp.com/hc/en-us/articles/360043033952-Formatting-Guide)：富文本、Markdown 及兼容性。
- [LinkedIn 发布动态](https://www.linkedin.com/help/linkedin/answer/a527227)：动态与文章入口；账号能力以当前页面为准。
- [X 帖子类型](https://help.x.com/en/using-x/types-of-posts)：普通帖与订阅长帖区分。
- [YouTube Shorts 帮助](https://support.google.com/youtube/answer/15424877)：实际时长、格式与版权资格核查入口。

修改配置后运行 `node scripts/upgrade_workflow.cjs`，同步平台规则、输入 schema、输出 schema 和工作流，然后执行回归测试。涉及平台硬限制时重新查官方来源，记录日期和适用内容形态，不能用本手册建议替代规则核验。
