# 文章、软文、图文、视频完整生产链路

版本：1.0；整理日期：2026-10-04。

用途：作为当前 skill 的端到端操作规范，规定每一步的输入、产出、检查、责任和失败回退。它不是已经实现的自动化引擎。现有脚本/工作流实际能力见第十节；未接入的制作或发布步骤须由人工或经过授权的外部工具完成，并记录证据。

## 一、链路总览

```text
S01 需求与交付范围
  → S02 素材、来源、权利与商业事实
  → S03 选题角度、承诺与内容策略
  → S04 大纲、初稿与类型规划
  → S05 文案审核及限次修订
  → S06 平台适配与文案定版
  → S07 类型制作
       文章：正文排版、必要配图、导出
       软文：商业审核叠加在文字/图文/视频制作上
       图文：素材 → 卡片排版 → 实际图片
       视频：素材 → 配音 → 真实时间轴 → 字幕 → 合成
  → S08 成品验收及人工终审
  → S09 发布包交付、目标账号预览与发布授权
  → S10 实际发布与回执核验（有单独授权才执行）
  → S11 数据采集、复盘、归档与受控迭代
```

共用原则：事实先于表达，内容先于包装，实际产物先于完成声明。每个阶段可返回上游，不得通过无证据的“通过”填满流程。

## 二、四类内容的关系

| 用户类型 | 生产形态 | 内容目标 | 专用交付 |
| --- | --- | --- | --- |
| 文章 | 文字及必要配图 | 解释、论证、经验或方法 | 正文、选定标题、摘要、来源与排版稿 |
| 软文 | 文字、图文或视频 + 商业表达 | 有依据地介绍产品/服务 | 商业声明证据、披露及购买路径检查 |
| 图文 | 多页卡片或图文组合 | 用图片与文字协同传递信息 | 实际图片、页序、说明、素材来源 |
| 视频 | 实拍、录屏、模板或生成式镜头 | 以音画完成解释、演示或叙事 | 实际成片、封面、字幕、音画与素材记录 |

需求记录推荐分开：`content_type=article|image_text|video`、`commercial_mode=none|promotion`。用户说“软文”时，明确最终是文字、图文还是视频，再启用商业审核。此分类是本规范约定，不是现有 runner 新增的输入字段。

## 三、职责与阶段检查

角色可以由同一个人兼任，但写作、事实核对、媒体验收、商业审批和发布授权必须留下不同职责的记录。模型评审不能替代人工审批、事实核验或原生平台预览。

| 阶段 | 输入 | 必须产出 | 进入下一阶段的条件 | 负责人/失败回退 |
| --- | --- | --- | --- | --- |
| S01 需求 | 用户目标、平台、交付要求 | 创作简报、任务范围、预算、交付项及权限 | 形式、受众、目的可确定；缺失项标记并补问 | 需求负责人；需求不清回到采集 |
| S02 素材 | 简报、用户素材、授权检索结果 | 事实表、素材权利表、待核实项、商业事实包 | 关键主张有支持材料；不能确认的内容删去、改为有边界表达或明确待核实 | 素材/事实负责人；缺证据暂停有关主张 |
| S03 策略 | 已知事实、受众与平台 | 不同候选角度、标题承诺、选定理由 | 承诺可兑现，角度有实质差异，非只追求刺激 | 编辑；回到选题或补素材 |
| S04 创作 | 策略与证据 | 大纲、初稿、主张关联、卡片/镜头规划 | 内容完整，不虚构经历与数据；规划符合生产形态 | 作者/模型；回到大纲或证据 |
| S05 文案审稿 | 初稿与证据表 | 事实/风格/表达/传播审稿、问题及修订稿 | 阻断问题已解决，语义未知项有人工处理；轮次与预算未超限 | 编辑与事实审稿；限次回到 S04 |
| S06 平台定版 | 修订稿、平台规则 | 实际标题、摘要、封面文字、正文、标签、分块与版本 | 实际发布组合兑现承诺，改写后事实与边界未丢失 | 平台编辑；问题回到 S05/S02 |
| S07 制作 | 定版文案、媒体计划、授权素材 | 类型成品、制作记录、素材与时间轴关联 | 实际文件存在且可读取；提示词、规划或任务提交不算完成 | 制作人员/已接入工具；按失败类型重制 |
| S08 成品验收 | 成品及来源、权利、披露 | 类型检查报告、问题修复、人工结论 | 关键缺陷处理完毕；商业/行业问题由合适人员复核；批准绑定实际版本 | 终审人；文案问题回到 S05，媒体问题回到 S07 |
| S09 发布准备 | 已验收版本与发布配置 | 发布包、原生预览记录、版本匹配的发布授权或“仅交付”结论 | 发布文本、媒体和披露一致；账号、渠道、时间、版本明确 | 交付/账号负责人；预览问题回到 S06/S07 |
| S10 发布 | 实际账号权限及明确授权 | 平台返回结果、发布 ID/链接、可见性核验及异常记录 | 不仅 API 成功，还核验实际目标内容；未经授权不执行 | 发布人员；失败记录，不冒充已发布 |
| S11 复盘 | 实际发布及观察窗口 | 指标快照、编辑反馈、假设、改进建议、档案 | 数据口径与窗口明确；变更规则有人工决定和验证 | 运营/编辑；缺数据保留未知 |

仅交付任务在 S09 完成，S10 标记 `not_requested`，S11 可记录交付反馈但不编造发布数据。用户授权写作或生成媒体不自动授权公开发布、定时发布或无上限付费调用。

## 四、统一输入与可追溯资料

使用 [任务模板](../templates/content-production-task.md)，为每项任务记录：

- 标识：`content_id`、任务目的、负责人、截止时间与当前交付范围。
- 创作：生产形态、商业属性、读者、核心问题、判断、语言、作者风格、禁写内容。
- 平台：平台键、内容形态、目标账号与渠道、当前规范核查日期。
- 素材：原始资料、出处、日期、真实经验、引用授权、敏感信息处理。
- 事实：`claim_id`、主张、`source_id`、来源位置/片段、适用条件、核验状态、核验人和时间。
- 商业：品牌与商品、合作关系、允许/禁止声明、证据、价格时效、目标地区、购买路径、披露及审批。
- 媒体：画幅、分辨率、字体/视觉模板、目标时长、声音、素材权利、可访问性和导出要求。
- 预算：文本修订次数、媒体重试次数、费用上限、超限处理与付费工具权限。
- 交付：文案、图片、成片、字幕、发布包、审核记录和是否实际发布。

事实状态推荐：`supplied`（仅提供）、`verified`（已人工核对）、`disputed`、`missing`。这些是记录用语；现有 facts 字段 `{id, claim, source}` 不会自动产生 verified 状态。产品提供的材料也不能直接替代独立核验。

素材权利状态推荐：`owned`、`licensed`、`permission_pending`、`unknown`。有来源链接不等于有商用授权；人物、声音、品牌资产、配乐分别检查。只上传经允许共享的数据，不把用户隐私或秘密交给未经授权的外部服务。

版本链：主题/事实版本 → 文案版本 → 平台版本 → 媒体版本 → 审核记录 → 发布包 → 发布回执 → 指标记录。每个媒体块关联原文单元和对应事实；文本、图片或披露变化后，下游审核和批准必须重新确认。

## 五、文章链路

```text
简报 → 来源与事实 → 角度比较 → 证据化大纲
→ 完整初稿 → 文案审核/修订 → 平台标题与正文定版
→ 原生排版/必要配图 → 成稿检查 → 发布包 → 授权发布 → 复盘
```

1. 根据任务选解释、观点、经验、案例或教程；不把所有文章固定为同一套段落。
2. 每节明确要推进的判断、证据和适用边界；事实与意见分别表达。
3. 真实案例与采访需可追溯；没有作者经历时不能写成亲身体验。
4. 先处理证据与结构，再处理套话、语气和节奏；规则扫描只是辅助。
5. 对实际标题、导读、封面文字和正文做最终核对；标题候选不能抵消实际标题的问题。
6. 按平台处理标题层级、列表、引用、图注、代码、链接和移动端排版，不假定 Markdown 普遍渲染。

完成标准：有完整正文文件和明确选定标题；关键主张支持关系可检查；重要限制保留；审稿问题有处置；目标排版经过所需检查。文章附实际配图时也执行图像检查。若只要求 Markdown 交付，原生发布预览仍明确为未执行。

## 六、软文链路（商业审核叠加）

```text
品牌/商品/合作关系 → 商业事实与证据 → 内容策略
→ 场景、真实体验、案例或对比 → 产品机制与取舍
→ 声明核对 + 披露与购买路径检查
→ 对应文字/图文/视频制作 → 成品商业复审 → 人工批准 → 授权发布
```

1. 明确关系：自有商品、付费合作、赠品、佣金或其他关联；不能伪装无关联推荐。
2. 选择场景解决、真实体验、案例、对比或品牌故事；以现有证据决定能采用哪种方式。
3. 建立“卖点主张 → 支持材料 → 比较条件 → 有效日期 → 适用边界”表。
4. 写清产品如何解决问题、需要什么条件、有哪些不足以及谁不适合；不能只靠情绪制造需求。
5. 没证据的效果、排名、评价、销量、优惠和稀缺性不能生成成事实；不能虚构测评或客户。
6. 在目标地区、行业、平台核查可识别性、商业披露与必要审批；需专业审查时保留人工门禁。
7. 核对实际购买路径与前文一致，包括版本、价格日期和条件；标记广告并非禁止内容的豁免。
8. 图文/视频里的文字、口播、字幕和画面也属于审核对象，不能只审正文。

完成标准：除对应生产形态的成品外，必须交付商业声明证据表、披露文字及位置、限制条件、购买路径检查和审批结论。未知或证据缺失不由高传播分补偿。

商业合规具体适用须核验，不以模型或此文档代替法律意见。参考依据与地区区别见 [调研报告](../reports/content-generation-research-2026-10-04.md)。广告披露与生成合成内容标识分别处理，不通过“降 AI 味”隐藏必要标识。

## 七、图文链路

```text
定版内容 → 单页/多页信息架构 → 视觉说明与素材清单
→ 真实素材、授权素材或生成插画 → 可控排版与文字层
→ 实际图片导出 → 逐页及页间验收 → 封面/说明/标签 → 原生预览
```

1. 确定是文章配图、解释图表还是社交卡片；每张有明确作用，不为凑页数加图。
2. 每页记录主题、主文案、依据、素材、顺序和与前后页的关系；封面承诺由后文兑现。
3. 准备视觉说明：画幅、标题层级、字号策略、边距、字体、对比度、参考图和安全区。
4. 事实场景、实测截图和商品外观优先用真实授权素材；生成插画不能冒充事实证据。
5. 生图采用“候选 → 核对主体/构图 → 必要局部修订”；关键文字、价格、数据和免责声明优先用可控文字层。
6. 图表由已核对数据制作，保留口径和来源；不能让生成模型自由画数字当结果。
7. 导出全部实际图片，记录规格、顺序、文件及素材来源；不能拿 cover_prompt 或 blocks 冒充图片。
8. 逐页核对文字准确、溢出、裁切、层次、阅读对比度；检查跨页遗漏/重复、主体一致性、图注、权利和披露。

完成标准：实际图片可打开，页序完整、正文可读，封面/说明/标签齐全，视觉和事实检查有记录。OCR 和自动检查可辅助，不能代替实际视觉审看。不同平台比例需重新排版/预览，不能只强行裁切。

## 八、视频链路

```text
定版脚本 → 分镜 → 制作路线与授权素材
→ 拍摄/录屏/模板画面/生成镜头 → 配音录制或合成
→ 真实时长测量 → 转写/对齐 → 字幕与时间轴
→ 剪辑合成/混音 → 实际成片 → 完整播放验收
→ 封面/简介/字幕/来源 → 原生预览 → 授权发布
```

### 8.1 路线选择

| 情况 | 首选路线 | 附加检查 |
| --- | --- | --- |
| 真实经历、产品操作、教程 | 实拍或录屏 + 辅助剪辑 | 信息真实性、画面隐私、演示结果 |
| 知识卡片、清单、解释型系列 | 图片/图表 + 配音 + 模板合成 | 音画对应、文字可读、避免机械节奏 |
| 非纪实创意或辅助镜头 | 文生、图生、关键帧或参考生视频 | 主体一致性、动作、时序、事实误导与成本 |
| 经授权的虚拟讲解 | 数字人 | 形象和声音权利、口型、商业用途与标识 |

选工具前明确素材、可控性、预算和交付要求；具体工具输入、价格、权限与许可证另行核查。生成镜头并非所有视频的必选步骤。

### 8.2 分镜到成片

分镜表每行至少有：`shot_id`、内容目的、口播、屏幕文字、画面/动作、素材 ID、事实 ID、来源和权利、预估时长、实际时长。脚本阶段的时间只作预算。

实际流程：

1. 审定讲述结构；缺少事实证据先返回素材阶段。
2. 准备镜头或关键帧；生成提示词围绕主体、动作、运镜与时间变化，不复制整篇文章。
3. 逐镜头检查；发现失真、错误商品、误导画面或主体断裂时只重制有关镜头，并重新检查连接处。
4. 准备录音/配音，核对数字、专有名词、停顿、授权和发音。
5. 测量真实音频/视频时长，通过转写或对齐得到字幕时间；无真实音频不得声明完成字幕同步。
6. 依据语义剪辑：画面对应口播，合理安排停顿、转场、字幕和音乐，避免文字遮挡主体与平台按钮。
7. 导出实际视频；保存封面、字幕、时间轴与引用/素材记录。
8. 从头到尾播放，检查起中末、音画同步、字幕、事实、闪帧/黑帧、静音、主体连续性和披露；抽帧不能代替完整播放。

完成标准：实际成片可播放，规格符合约定，音画和字幕检查有证据；素材与声音授权记录可查。视频脚本、分镜、API 任务 ID 或下载链接本身不算成片验收。目标平台转码后的效果在上传/发布阶段另查。

## 九、状态、失败处理、发布与复盘

### 9.1 不混用生命周期状态与 runner 状态

本规范建议记录生命周期里程碑：`brief_confirmed`、`evidence_ready`、`copy_reviewed`、`platform_copy_ready`、`artifact_exported`、`artifact_reviewed`、`human_approved`、`delivery_complete`、`published_verified`、`archived`。这些不是现有 runner 的输出枚举，也不代表程序自动校验过。

各阶段同时记录 `pending|in_progress|passed|needs_revision|blocked|not_requested`，附原因与证据。实际不需要的媒体步骤标记 not_requested，不能伪造 passed。现有 `ready_for_human_review` 只表示进入人工审核，不是 human_approved；本地 `needs_human_review` 保留其原有含义。

批准记录绑定 `content_id`、文案/成品/发布包版本、批准人、批准时间、范围、目标平台和账号。任何影响事实、披露、画面或发布组合的变更，都令有关下游批准失效。

### 9.2 失败回退与停止

| 问题 | 回退 | 停止条件 |
| --- | --- | --- |
| 事实缺失/冲突 | S02，删除有关主张或补证据 | 关键结论无法支持，不进入交付批准 |
| 角度或标题不能兑现 | S03/S05，改承诺或重选角度 | 禁止以刺激度替代准确性 |
| 文案/平台格式错误 | S04/S06，局部修订后复审 | 达到约定轮次则转人工，不无限循环 |
| 生图/镜头失真 | S07，修有关素材并检查下游 | 重试/费用上限到达或授权不明则停止 |
| 配音/字幕/渲染失败 | S07，修音频、时间轴或合成 | 未有可验收文件不标完成 |
| 商业或权利问题 | S02/商业复核 | 未取得必要证据/授权/审批不放行 |
| 发布异常 | S09/S10，保留实际错误 | 不重复提交未知结果，不切换账号绕过权限 |

预算与轮次由用户需求决定。现有文本 `max_rounds` 的共享上限保持不变；新增媒体重试预算应单独约定，不冒充已有自动限制。网络失败重试前确认是否可能已生成/计费，尽可能按任务 ID 查状态，避免重复提交。

### 9.3 发布包与授权

发布包至少包含：选定标题、封面、摘要/简介、实际正文/媒体、页序/字幕、必要标签、来源、商业披露和必要 AI 标识、目标平台/账号/时间、审核记录与当前版本。

只有明确的发布授权和匹配版本才进入 S10。交付稿件不等于账号已登录、平台允许发布或作品已公开。若需定时发布，另行确认计划与工具能力，不以文档里的时间字段自动创建任务。

记录实际返回结果并核验目标内容，区分提交成功、平台审核中、实际可见、受限、失败；不能统一写为已发布。结果未知时先查询，不盲目重复提交。

### 9.4 复盘与归档

每个平台/变体记录发布 ID、版本、观察开始/结束、时区、指标定义和可获得数据。文章关注有效阅读、收藏、评论；图文关注实际可取得的阅读/互动；视频关注观看、时长与完播；商业内容另看可归因的点击和转化。

不要把 reads 当 video plays，也不要伪造平台未提供的卡片翻页数据。缺失分母留空，口径不一致不直接比较。观察性结果只生成假设，不证明标题/提示词导致增长；规则与阈值更新经人工复核并保留回滚版本。

现有 `scripts/editorial.py` 仅支持其已定义指标，不支持的指标另存并写定义；计数应为整数。`scripts/calibrate_reviews.py` 校准审稿判断，不预测流量、不自动修改阈值。归档包括简报、来源、素材、版本、模型/工具参数、实际花费、审核、交付与发布记录；敏感数据按实际授权和留存要求管理。

## 十一、交付包组织

按任务范围组织实际文件；下面是推荐目录，不要求为空缺能力创建假文件。每个目标平台/内容形态使用独立 variant_id，共享事实包但分别审核与记录结果。

```text
<content_id>/
  task.md                 简报、阶段、授权与实际结果
  evidence/               事实表、来源记录、商业声明及素材权利
  copy/<variant_id>/      文案、大纲、实际标题、摘要与发布说明
  media/<variant_id>/     实际图片/音频/视频、字幕、时间轴及制作记录
  reviews/<variant_id>/   文案与成品检查、人工批准及其绑定版本
  delivery/<variant_id>/  已验收的发布组合、文件清单及预览记录
  publication/            实际发布回执、状态与可见性核验
  feedback/               指标快照、观察口径、复盘与变更决定
```

交付清单记录文件路径、用途、规格、版本、对应主张/素材及检查结果。自动化批量处理时推荐加文件校验值，确保批准、交付和发布对应同一产物。未请求发布时 publication 不需要存在，但 task.md 中保留 not_requested。

跨平台复用流程：选定共同事实与观点 → 各自调整篇幅和信息顺序 → 各自制作 → 各自验收 → 各自授权及回执。翻译需单独核对原意、数字与商业声明，不能把设置 language 当作已经翻译。

## 十二、验收情景

| 情景 | 应有处理 |
| --- | --- |
| 只有主题，没有经验或来源 | 补问/补素材；不编造作者经历，不宣称事实核验完成 |
| 要求“用了一个月”的软文，但没有试用记录 | 不写虚构体验；改成有来源的产品介绍，保留商业审查 |
| 图文只有卡片文字或提示词 | 交付标记为工作稿，图片阶段未完成 |
| 视频只有脚本或生成任务 ID | 未验收成片，等待真实文件、音频与播放检查 |
| 同一素材改成文章、图文和视频 | 共享事实来源，各自制作与审核；不复制同一个完成状态 |
| 人工批准后修改封面卖点 | 更新版本，重新商业/成品检查及批准 |
| 已生成文件但没有发布授权 | 交付发布包，不发平台、不自动排期 |
| 流量上涨但没有可比实验 | 记录观察与假设，不声称因果或自动更新阈值 |

按 [任务模板](../templates/content-production-task.md) 为真实任务逐项记录。模板空白、规划、模拟或单元测试通过，都不构成相应制作/审批/发布阶段通过。
